# Policy Exception Request

> **Form.** Copy this file to record a request to waive a specific policy requirement. Exceptions
> are time-bound (maximum 12 months), risk-assessed, and must include compensating controls.
> See [Policy Framework §5](../docs/policy-framework.md).

## 1. Request Metadata

| Field | Value |
|-------|-------|
| Exception ID | EXC-<YYYY>-<NNN> |
| Date Requested | <YYYY-MM-DD> |
| Requester (role) | <role — never a personal name> |
| Policy / Clause | <e.g. POL-ACC-003 §6.3> |
| Requirement to be waived | <quote the exact requirement> |
| Requested Duration | <start> to <expiry, max 12 months> |

## 2. Business Justification

<Why the requirement cannot be met as written, and the business need for the exception.>

## 3. Risk Assessment

| Field | Value |
|-------|-------|
| Risk introduced | <description> |
| Likelihood | Low / Medium / High |
| Impact | Low / Medium / High |
| Inherent risk rating | Low / Medium / High / Critical |
| Data affected (classification) | <Public / Internal / Confidential / Restricted> |
| Personal data involved? | Yes / No (if Yes, DPO sign-off is mandatory) |

## 4. Compensating Controls

<List the controls that reduce the residual risk while the exception is in force.>

## 7. Review and Closure

| Field | Value |
|-------|-------|
| Status | Requested / Approved / Rejected / Expired / Closed |
| Expiry Date | <YYYY-MM-DD> |
| Closure Evidence | <link to remediation evidence in `jol-compliance-evidence`> |

> Approved exceptions are logged and tracked to expiry. Expired exceptions lapse automatically and
> must be re-approved or remediated. Recurring exceptions trigger a policy review.
